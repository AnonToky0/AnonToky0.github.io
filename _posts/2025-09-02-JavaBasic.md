## 元注解
Java中的元注解是用来修饰注解的注解，常见的有以下几种：

| 元注解       | 作用               | 说明         |
|--------------|-------------------------------|-------------------------------------------|
| `@Retention` | 指定注解的生命周期| 如 `SOURCE`、`CLASS`、`RUNTIME`                              |
| `@Target`    | 指定注解可以应用的Java元素类型 | 如 `TYPE`（类、接口）、`METHOD`（方法）、`FIELD`（字段）等   |
| `@Documented`| 指示注解是否包含在Javadoc中    | 如果使用该注解，注解信息会被Javadoc工具提取出来，默认不包含   |
| `@Inherited` | 指示注解是否可以被子类继承  | 只对类注解有效，子类会自动继承父类的注解   |

## InsertClassVisitor 工作机制
负责将Hook方法织入到目标类的指定方法。
### 主要流程
1. 类级别处理
- 当 ASM 访问到一个类时，visit 方法会被调用。
- 通过 executeInfos.get(getContext().name) 获取当前类所有需要插入的 InsertInfo（即所有与该类相关的 hook 规则）。
- 这些 InsertInfo 会在后续方法遍历时用到。

2. 方法级别处理
- 遍历类的每个方法，查找与 InsertInfo 匹配的方法（方法名和方法签名一致）。
- 校验 static 修饰符是否一致（hook 方法和目标方法必须同为 static 或非 static）。

- 如果找到匹配项且方法不是 native/abstract：
    - 生成一个“孪生”方法（newName = name + "$twin"，私有），保存原始方法逻辑。
        - 构建 MethodChain，将所有 hook 方法链式织入到目标方法。
            - chain.headFromInsert：记录孪生方法的头部信息。
            - chain.next：将每个 hook 方法按顺序加入链条。
            - chain.fakePreMethod：生成一个“假方法”，用于后续织入。
    - 最终用 super.visitMethod 新增孪生方法，原方法将被 hook 逻辑替换。

3. 生成 super 调用（visitEnd 方法）
- 有些 hook 规则要求在插入逻辑中能访问父类的原始方法（createSuper 标记）。
- visitEnd 会自动为这些方法生成一个方法体，调用 super.method 并返回结果，- 保证 hook 后仍可访问原始父类逻辑。

## 垃圾回收机制(Garbage Collection, GC)
Java 是一种带有自动内存管理的语言，垃圾回收机制负责自动释放不再使用的对象所占用的内存，避免程序出现内存泄漏和内存溢出。

垃圾回收主要发生在 堆内存 中。Java 堆是**所有对象实例**的存储区域。

堆内存一般划分为几个区域：
- 新生代（Young Generation）：存放新创建的对象
- 老年代（Old Generation）：存活时间较长的对象会被移到这里
- 永久代/元空间（PermGen/Metaspace）：存放类的元数据

### 基本原理
GC 的核心是判定哪些对象是“垃圾”，即不再被任何活动的线程或变量引用。

主要判定方法：
- 引用计数法：给对象维护一个引用计数，计数为0时回收（**Java 不采用此法**，因为循环引用问题）。
- 可达性分析算法（Reachability Analysis）：从一组称为“GC Roots”的对象开始，沿引用链搜索所有可达对象，未被可达的对象视为垃圾。

### 垃圾回收算法
1. 标记-清除
- 标记阶段：标记所有需要回收的对象。
- 清除阶段：清除被标记的对象，释放内存。

缺点：会产生大量不连续的内存碎片。

2. 复制算法
- 将内存分为两块，每次只使用一块，另一块为空闲。
- 把存活对象复制到空闲区，清理掉原来区域所有对象。

优点：没有内存碎片，适合新生代。

3. 标记-整理
- 标记阶段同标记-清除。
- 整理阶段，把存活对象向一端移动，清理端边界以外的内存。

避免了碎片问题，但移动对象需要额外开销。

## 引用(Reference)
Java 中的引用, 本质上是一个指向对象的“句柄”或“指针”的抽象，但它不是一个内存地址的变量，而是由 JVM 管理的一种对对象的间接访问方式。
- 它指向堆上的一个对象实例。
- 通过引用来访问对象的属性和方法。
- 引用本身不能做算术运算，也不能直接操作内存。
- 引用可以是 null，表示不指向任何对象。

- 引用变量存储的是对象的引用信息，但这个信息对程序员是透明的，程序员看不到具体的内存地址。
- Java 通过引用来实现“传递对象”的机制（传递引用的副本）。
- **引用是对象的别名**，引用本身不可变（不能指向其他对象），但对象内容是可变的。

| 特性             | Java引用                     | C++指针                      |
|------------------|------------------------------|------------------------------|
| 是否直接存储内存地址 | 否，JVM管理引用的具体实现          | 是，变量存储实际内存地址           |
| 是否支持指针运算   | 否                            | 是                            |
| 是否可以修改指向   | 否，引用一旦指向某对象不可变         | 是，可以改变指针指向             |
| 是否需要手动管理内存 | 否，JVM自动垃圾回收               | 是，程序员需手动管理内存          |
| 是否能为null       | 可以                         | 可以                         |

## JDK、JRE、JVM
### JVM(Java Virtual Machine)
- java虚拟机，是java程序运行的核心引擎
- 负责加载、验证、执行java字节码
- 提供内存管理、垃圾回收、安全机制等运行时环境
- “一次编写，到处运行”的关键：将字节码翻译成不同平台的机器码

### JRE(Java Runtime Environment)
- java运行环境，**包含JVM+基础类库**
- 提供java程序运行的最小环境
- 包含标准API、核心库(如java.lang, java.util等)
- 只能运行Java程序，不能开发java程序

### JDK(Java Development Kit)
- java开发工具包，**包含JRE+开发工具**
- 开发人员使用的完整套件
- 包含编译器(javac)、调试器、文档工具等

## 杂项
### 矩阵乘法的计算开销
- 矩阵乘法的计算量是按顺序累积的。
- 对于两个矩阵 `X(a×b)` 和 `Y(b×c)`，乘法计算量是 `a×b×c` 次标量乘法。
- 不同的括号方式（乘法顺序）对应不同的计算量。

#### 计算举例
假设有3个矩阵：
- A: 10*100
- B: 100*5
- C: 5*50

两种乘法顺序:
- 先计算A\*B: 10\*100\*5 + 10\*5*50 = 7500
- 先计算B\*C: 100\*5\*50 + 10\*100*50 = 75000

### private
java中 private不能应用在局部变量，因为局部变量的作用域本身就是方法或代码块内。
> 注意，c++也不行，别和static关键词搞混，private是针对类成员的访问权限限制。

### 哈夫曼编码(Huffman Coding)
哈夫曼编码是一种广泛使用的无损数据压缩算法。它通过构建一棵特殊的二叉树，实现对数据中不同符号的变长编码，达到压缩数据的目的。

### 基本思想
哈夫曼编码根据符号出现的频率（或概率）来分配编码，出现频率高的符号用较短的编码，出现频率低的符号用较长的编码，从而减少整体编码长度。

#### 特点
- 前缀码：任何一个编码都不是另一个编码的前缀，保证编码唯一可解码。
- 最优性：在给定符号概率的情况下，哈夫曼编码能生成平均编码长度最短的前缀码。

### 输入/输出流

**字符（char）** 在 Java 中是以 **16位（2字节）** 的 Unicode 编码来表示的。

#### 字符和字节IO

| 流类型   | 处理的数据单位           |
|----------|------------------------|
| 字节流   | 以字节（byte，8位）为单位处理数据，适合所有类型的数据（文本、图片、音频、视频等） |
| 字符流   | 以字符（char，16位Unicode字符）为单位处理数据，专门用于处理文本数据 |

- 字节流设计为处理原始的二进制数据，不涉及字符编码转换。
- 字符流设计为处理文本数据，自动处理字符编码和解码（如UTF-8、UTF-16等），更方便读写文本。

#### 常见流对比

| 功能             | 字节流类（InputStream/OutputStream） | 字符流类（Reader/Writer）     |
|------------------|-------------------------------------|------------------------------|
| 读取文件         | `FileInputStream`                   | `FileReader`                 |
| 写入文件         | `FileOutputStream`                  | `FileWriter`                 |
| 缓冲处理         | `BufferedInputStream`               | `BufferedReader` / `BufferedWriter` |
| 转换桥接         | —                                   | `InputStreamReader` / `OutputStreamWriter` |

#### 字符输入/输出流
字符输出流的抽象基类：java.io.Writer
字符输入流的抽象基类：java.io.Reader

#### 字节输入/输出流
字节输入流的抽象基类：java.io.InputStream
字节输出流的抽象基类：java.io.OutputStream

## protobuf
Protobuf 是 Google 开发的一种高效、灵活的结构化数据序列化机制。

### 数据编码格式
Protobuf 使用一种紧凑的二进制编码格式，主要特点是：
- 变长编码（Varint）：整数采用变长编码，节省空间。
- 键值对结构（Key-Value）：每个字段由一个“键”和“值”组成。
- 字段顺序不敏感：字段可以任意顺序出现。
- 支持多种数据类型：整型、浮点、字符串、嵌套消息等。

### 字段编码结构
Protobuf 中每个字段编码为：

```
key + value
```

key 是一个变长整数（varint），包含两部分：
    - 字段号（field number）：标识字段的唯一编号。
    - 类型（wire type）：标识字段的数据类型，决定如何解析后面的值。

编码方式：

```
key = (field_number << 3) | wire_type
```

#### wire_type（线类型）

| wire_type | 含义                 | 说明                          |
|-----------|----------------------|-------------------------------|
| 0         | varint               | int32, int64, bool, enum 等   |
| 1         | 64-bit               | fixed64, double               |
| 2         | length-delimited     | string, bytes, embedded message, repeated packed fields |
| 5         | 32-bit               | fixed32, float                |


#### 变长编码(Varint)
- 变长整数编码方式，低7位存数据，高1位作为是否还有后续字节的标志。  
- 例如数字300 编码：
    - 二进制：`100101100`
    - 分为7位一组：`00101100`, `00000010`
    - 编码为两个字节：`10101100`, `00000010`
- 这样能节省小数字的存储空间。

#### 序列化流程
- 按照 `.proto` 文件定义的消息结构，遍历每个字段。
- 对每个字段：
    - 计算 key（字段号 + wire type）。
    - 将 key 用 varint 编码写入缓冲区。
    - 根据字段类型，将字段值编码写入缓冲区。
- 对嵌套消息，先序列化嵌套消息，再写入长度和内容（length-delimited）。

### protobuf 和 json 比较

| 特性           | Protocol Buffers (protobuf)                      | JSON                                     |
|----------------|-------------------------------------------------|------------------------------------------|
| **数据格式**   | 二进制格式                                      | 文本格式（可读性强）                      |
| **性能**       | 序列化和反序列化速度快，占用空间小              | 速度较慢，占用空间较大                    |
| **可读性**     | 不可读，需要工具解析                            | 可读，易于调试和查看                      |
| **跨语言支持** | 支持多种语言（C++, Java, Python 等）            | 几乎所有语言都支持                       |
| **模式定义**   | 需要提前定义 `.proto` 文件，严格的模式           | 无需模式，灵活，动态结构                  |
| **扩展性**     | 支持向后兼容，字段可以新增或废弃                 | 灵活但无严格版本控制，易出错               |
| **调试难度**   | 较难，需借助工具查看二进制数据                   | 简单，直接查看文本内容                     |
| **网络传输**   | 更小的数据包，节省带宽                           | 数据包较大                               |
| **使用场景**   | 高性能、高并发、资源受限环境（移动端、IoT、RPC） | 配置文件、日志、Web API、调试             |

## JSON
JSON（JavaScript Object Notation）是一种轻量级的数据交换格式, 广泛用于前后端数据传输。  

### json解析过程
JSON解析指的是将JSON格式的字符串转换成程序中可以操作的数据结构（如对象、数组等）的过程。

1. 词法分析 (Lexical Analysis / Tokenization)
把输入的JSON字符串分解成一系列的“记号”(Token)，如括号 {、}、方括号 [、]、逗号 ,、冒号 :，以及字符串、数字、布尔值、null等字面量。

``` json
{
  "name": "Alice",
  "age": 25
}
```

分解成的Token序列

``` json
{, "name", :, "Alice", ,, "age", :, 25, }
```

2. 语法分析 (Parsing)
根据JSON的语法规则，构建一个抽象语法树（AST）或直接构造对应的数据结构。过程为:
- 识别对象（用 {} 包围）和数组（用 [] 包围）。
- 解析键值对，字符串，数字，布尔值，null等。
- 递归处理嵌套结构。

``` json
Object
 ├─ Key: "name", Value: "Alice" (string)
 └─ Key: "age", Value: 25 (number)
```

3. 语义检查(Semantic Analysis)
确保数据符合JSON规范,包括键必须是字符串; 值必须是有效的JSON类型（字符串、数字、对象、数组、布尔值、null）。

4. 数据结构构建
- 将解析结果转换成程序语言中的数据结构：
    - 在 JavaScript 中，转换成对象（Object）和数组（Array）。
    - 在 C 语言中，可能转换成结构体、链表等。
    - 在 Python 中，转换成字典（dict）和列表（list）。
- 解析器会分配内存，存储对应的键值对和数组元素。

5. 解析完成
- 返回解析后的数据结构，供程序使用。
- 如果解析过程中发现错误（如格式错误、缺少逗号、引号不匹配等），则会返回错误信息。

### 解析
解析在序列化/反序列化的上下文中，指的是将数据从一种格式转换回程序内存中的数据结构的过程。
- 序列化（Serialization）：将程序中的数据结构（如对象、结构体）转换成一种可存储或传输的格式（比如二进制、文本）。
- 反序列化（Deserialization）或解析（Parsing）：将序列化后的数据还原成程序中的数据结构。

- Protobuf 也需要解析，只是它的解析是将二进制格式的数据转换成对应的对象或结构体。
- 解析过程由 protobuf 的库自动完成，开发者调用相应的接口即可，不必自己手写解析代码。
- 解析的效率通常比 JSON 等文本格式更高，因为 protobuf 是紧凑的二进制格式，结构明确，解析时无需处理复杂的文本格式。
